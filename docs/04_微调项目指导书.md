# SmolVLA 微调项目指导书

## 1. 目标

使用冻结并检查通过的本地 SO-100/SO-101 数据集，对 `lerobot/smolvla_base`
进行微调，生成可以在 LeRobot `0.4.3` 中本地加载和执行的检查点。

本项目固定使用：

```text
conda 环境: lerobot_043
Python: 3.10
LeRobot: 0.4.3
源码目录: /path/to/we_smolvla
基础模型: /path/to/we_smolvla/models/smolvla_base
训练方式: 默认动作专家微调
```

LeRobot `0.4.3` 没有可用的 LoRA/PEFT 训练器，因此本指导书不提供 LoRA 路线。
不推荐在 12 GB 显存上进行全部参数的全参数 AdamW 训练。

## 2. 前置条件

必须满足：

- `01_部署项目指导书.md` 已验收。
- `02_仿真测试项目指导书.md` 已通过短训练冒烟测试。
- `03_数据收集与格式处理项目指导书.md` 已完成数据检查和拆分。
- 训练集可以通过 LeRobot `0.4.3` 的 `LeRobotDataset` 正常读取。
- 训练集 state/action 为 6 维。
- camera key 和任务描述已经冻结。

版本和字段验收命令：

```bash
conda activate lerobot_043
cd /path/to/we_smolvla

python - <<'PY'
from lerobot.datasets.lerobot_dataset import LeRobotDataset

repo_id = "local/so101_pick_blue_cube"
root = "/path/to/we_smolvla/datasets/raw/so101_pick_blue_cube"
ds = LeRobotDataset(repo_id=repo_id, root=root)

print("codebase_version:", ds.meta._version)
print("fps:", ds.meta.fps)
print("episodes:", ds.num_episodes)
print("frames:", ds.num_frames)
print("features:", sorted(ds.features))
print("camera_keys:", ds.meta.camera_keys)
print("video_keys:", ds.meta.video_keys)
PY
```

如果该命令不能读取数据，先回到 `03_数据收集与格式处理项目指导书.md` 处理格式。

## 3. 12 GB 显存推荐配置

推荐起点：

```text
policy: /path/to/we_smolvla/models/smolvla_base
batch_size: 1
precision: BF16
freeze_vision_encoder: true
train_expert_only: true
train_state_proj: true
empty_cameras: 1
num_workers: 2
video_backend: torchcodec
```

`0.4.3` 的训练循环每执行一次就进行一次优化器更新，`--steps` 直接表示
optimizer updates，并且没有训练器梯度累积参数。不要把 batch size 乘以一个不存在
的 accumulation step。BF16 通过 `--policy.use_amp=true` 启用。

当前直接在磁盘上可用的原始数据是：

```text
repo_id: local/so101_pick_blue_cube
root: /path/to/we_smolvla/datasets/raw/so101_pick_blue_cube
observation.images.front
observation.images.wrist
```

该原始副本必须把摄像头字段映射到基础模型期望的 `camera1` 和 `camera2`：

```bash
--rename_map='{"observation.images.front":"observation.images.camera1","observation.images.wrist":"observation.images.camera2"}'
```

字段规范化副本位于：

```text
repo_id: local/so101_pick_blue_cube_camera12
root: /path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12
observation.images.camera1
observation.images.camera2
```

基础模型期望：

```text
observation.images.camera1
observation.images.camera2
observation.images.camera3
```

因此训练命令必须包含：

```bash
--policy.empty_cameras=1
```

字段规范化副本已经使用 `camera1` 和 `camera2`，不需要 `rename_map`。
当前磁盘还没有生成 `camera12_clean` 和 `camera12_split/train`，因此在完成数据清洗与
拆分前，训练命令必须使用上面的原始副本，不能引用不存在的 split 路径。
如果使用三个摄像头，并把摄像头直接命名为 `camera1`、`camera2`、`camera3`，
则不需要 `empty_cameras`。

## 4. 训练前环境设置

```bash
conda activate lerobot_043
cd /path/to/we_smolvla

export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
export TOKENIZERS_PARALLELISM=false
export HF_HOME=$HOME/.cache/huggingface
export HF_LEROBOT_HOME=$HOME/.cache/huggingface/lerobot
```

项目资产统一放在 `/path/to/we_smolvla`。Hugging Face 和 LeRobot 的系统缓存
继续使用当前已经存在且包含模型、校准文件的 `$HOME/.cache/huggingface`，不要改成
空目录，否则会重新下载模型或找不到已有校准文件。

检查 GPU：

```bash
nvidia-smi
```

关闭浏览器、QQ、Zotero 等不需要的大型程序，减少显存和内存占用。

如果模型已经在缓存中，可以启用：

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

需要下载模型时，单独打开联网终端，并确保代理配置中没有裸 `socks://`。

## 5. 动作专家微调冒烟训练

先用极少步数确认：

- 数据能读取。
- `camera1`、`camera2` 和 `empty_cameras` 能匹配模型输入。
- 反向传播能执行。
- 显存不会立即 OOM。
- 检查点能保存。

```bash
conda activate lerobot_043
cd /path/to/we_smolvla
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True

lerobot-train \
  --policy.path=/path/to/we_smolvla/models/smolvla_base \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --policy.freeze_vision_encoder=true \
  --policy.train_expert_only=true \
  --policy.train_state_proj=true \
  --policy.empty_cameras=1 \
  --dataset.repo_id=local/so101_pick_blue_cube \
  --dataset.root=/path/to/we_smolvla/datasets/raw/so101_pick_blue_cube \
  --dataset.video_backend=torchcodec \
  --rename_map='{"observation.images.front":"observation.images.camera1","observation.images.wrist":"observation.images.camera2"}' \
  --output_dir=/path/to/we_smolvla/outputs/train/smoke_expert_043 \
  --job_name=smolvla_so101_smoke_expert_043 \
  --batch_size=1 \
  --steps=200 \
  --num_workers=2 \
  --log_freq=10 \
  --eval_freq=0 \
  --save_freq=100 \
  --policy.use_amp=true \
  --wandb.enable=false
```

说明：

- `--eval_freq=0` 关闭训练中的仿真环境评估。
- `0.4.3` 不支持 `--dataset.eval_split`。
- `0.4.3` 不支持 `--eval_steps`。
- `0.4.3` 不支持 `--env_eval_freq`。
- `0.4.3` 不支持 `--peft.*`。
- `--policy.empty_cameras=1` 必须与两个实际摄像头配合使用。

## 7. 默认微调行为

`lerobot/smolvla_base` 默认配置为：

```text
freeze_vision_encoder=true
train_expert_only=true
train_state_proj=true
```

这表示视觉编码器和 VLM 主干冻结，只训练动作专家和状态投影。它比全参数训练更接近
论文设置，并且比全参数 AdamW 更适合 12 GB 显存。

如果 OOM：

1. 将 `batch_size` 保持为 1。
2. 将 `num_workers` 降到 2。
3. 关闭所有不需要的桌面程序和后台进程。
4. 保持 `wandb` 关闭。
5. 不要改用 `0.4.3` 不存在的 LoRA/PEFT 参数。

## 8. 学习率和训练变量

保守起点使用基础模型保存的学习率：

```text
optimizer_lr: 1e-4
scheduler_decay_lr: 2.5e-6
```

如果 loss 不稳定，可以尝试：

```bash
--policy.optimizer_lr=5e-5 \
--policy.scheduler_decay_lr=1e-6
```

一次实验只改变一个变量。不要同时大幅提高 batch size 和 learning rate。

12 GB 显存建议按以下顺序建立记录：

```text
E0: base 模型，不训练，仅本地评估
E1: expert-only, batch=1
E2: expert-only, batch=2
E3: expert-only, batch=1, 较低 learning rate
```

E0 必须作为对照。

## 9. 训练中的监控

终端重点观察：

```text
loss
grad_norm
lr
step_s
gpu_mem_gb
```

另开终端：

```bash
nvidia-smi dmon -s pucm
```

GPU 占用查询：

```bash
watch -n 1 'nvidia-smi --query-gpu=memory.used,memory.free,utilization.gpu,temperature.gpu --format=csv,noheader'
```

需要停止训练的情况：

- 显存持续接近 12 GiB，频繁出现碎片 OOM。
- loss 变为 NaN 或 Inf。
- 数据加载 worker 持续崩溃。
- 训练速度异常低且 GPU 利用率长期接近 0。
- 检查点无法写入磁盘。

## 10. 检查点

训练输出通常位于：

```text

```

检查：

```bash
find /path/to/we_smolvla/outputs/train/smolvla_so101_expert_v1/checkpoints \
  -maxdepth 3 -type f \( -name 'config.json' -o -name 'model.safetensors' -o -name 'train_config.json' \) \
  | sort
```


## 11. 恢复训练

如果训练中断，并且检查点目录中包含 `training_state/`：

```bash
conda activate lerobot_043
cd /path/to/we_smolvla

lerobot-train \
  --config_path=/path/to/we_smolvla/outputs/train/smolvla_so101_expert_v1/checkpoints/last/pretrained_model/train_config.json \
  --resume=true
```

恢复前确认：

- 数据集没有改变。
- task text 没有改变。
- camera key 没有改变。
- `empty_cameras` 没有改变。
- GPU 驱动和依赖没有升级。
- 输出目录没有被其他进程使用。

## 12. 验证策略

LeRobot `0.4.3` 的离线训练 CLI 没有 `dataset.eval_split` 和单独的验证 loss 循环。
本地数据训练使用以下验证：

1. 训练集 loss：判断是否能拟合。
2. 独立本地测试条件：判断是否能完成真实任务。
3. 如果配置了 LIBERO 环境评估，使用 `--eval_freq` 在仿真中评估检查点。

只有训练 loss 下降但真实测试失败时，优先检查：

- 数据归一化。
- 摄像头输入顺序。
- camera key 或相机物理位置。
- leader/follower 动作尺度。
- 推理时的动作执行步数。
- 推理时的任务文本。

训练 loss 仍然较高时，优先增加或修正数据，不先改大模型。
