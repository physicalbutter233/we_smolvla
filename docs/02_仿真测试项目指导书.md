# SmolVLA 仿真测试项目指导书

## 1. 目标

本阶段用 LIBERO 验证：

1. LeRobot `0.4.3` 和 LIBERO 环境可运行。
2. `lerobot/smolvla_libero` 可以加载。
3. `lerobot-eval` 可以执行策略并输出结果。
4. `lerobot-train` 可以执行短训练、保存和恢复检查点。
5. 12 GB 显存下的批大小和参数组合得到基线记录。

仿真的作用是验证软件链路，不是证明本地 SO-100/SO-101 任务已经可执行。

## 4. LIBERO 关键参数

本项目的 LIBERO 评估固定使用：

```text
env.type=libero
env.fps=20
env.control_mode=relative
policy.n_action_steps=10
eval.batch_size=1
env.max_parallel_tasks=1
seed=1000
```

原因：

- LIBERO 的 robosuite 默认控制频率为 20 Hz。
- 当前 `lerobot/smolvla_libero` 的保存配置把 `n_action_steps` 保留为 50。
- SmolVLA 在 LIBERO 上执行 10 个动作的 chunk 比执行 50 个动作更稳定。

LeRobot `0.4.3` 的 LIBERO CLI 没有 `--env.task_ids` 字段。当前 CLI 会评估
`--env.task` 指定的 suite 中的全部 task。需要控制测试规模时，使用以下方式：

```text
只跑一个 suite，每个 task 1 个 episode: --env.task=libero_spatial --eval.n_episodes=1
只跑一个 suite，每个 task 3 个 episode: --env.task=libero_spatial --eval.n_episodes=3
跑四个 suite，每个 task 10 个 episode:
  --env.task=libero_spatial,libero_object,libero_goal,libero_10
  --eval.n_episodes=10
```

`--eval.n_episodes` 表示“每个被选中的 task 执行多少个 episode”，不是整个 suite
总共执行多少个 episode。

## 5. 相机键映射

LIBERO 环境输出：

```text
observation.images.image
observation.images.image2
```

`lerobot/smolvla_libero` 使用：

```text
observation.images.camera1
observation.images.camera2
observation.images.camera3
```

评估时必须显式传入：

```bash
--rename_map='{"observation.images.image":"observation.images.camera1","observation.images.image2":"observation.images.camera2"}'
```

`0.4.3` 的评估入口会把顶层 `rename_map` 同时用于策略构造和预处理流程。

## 6. 代理和离线模型

`--policy.path` 只指定 SmolVLA 策略目录。SmolVLA 的配置中还有：

```text
vlm_model_name: HuggingFaceTB/SmolVLM2-500M-Video-Instruct
```

策略初始化时会单独加载该 VLM。模型已经缓存时，优先使用离线模式：

```bash
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY
unset http_proxy https_proxy all_proxy
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

如果出现：

```text
OSError: Unknown scheme for proxy URL URL('socks://127.0.0.1:7897/')
```

说明当前进程中存在裸 `socks://` 代理变量。`requests`、`httpx` 和
`huggingface_hub` 的组合不能直接识别该 scheme。永久修复方式是在宿主机图形桌面中
取消 SOCKS 代理项，只保留 HTTP 和 HTTPS 项，或者把代理改为
`socks5h://`。

检查 GNOME 代理：

```bash
gsettings get org.gnome.system.proxy mode
gsettings get org.gnome.system.proxy.http host
gsettings get org.gnome.system.proxy.http port
gsettings get org.gnome.system.proxy.https host
gsettings get org.gnome.system.proxy.https port
gsettings get org.gnome.system.proxy.socks host
gsettings get org.gnome.system.proxy.socks port
```

如果使用 SOCKS5，使用以下变量形式：

```bash
unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy
export ALL_PROXY=socks5h://127.0.0.1:7897
export all_proxy=socks5h://127.0.0.1:7897
```

不要把 `HTTP_PROXY` 或 `HTTPS_PROXY` 设置为 `socks://`。

## 7. LIBERO Spatial 小规模评估

该命令会评估 `libero_spatial` 的全部 task，每个 task 1 个 episode。当前
`libero_spatial` 有 10 个 task，因此总共执行 10 个 episode。

```bash
conda activate lerobot_043
cd /path/to/we_smolvla
export MUJOCO_GL=egl
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1

lerobot-eval \
  --policy.path=/path/to/we_smolvla/models/smolvla_libero \
  --policy.device=cuda \
  --policy.n_action_steps=10 \
  --env.type=libero \
  --env.task=libero_spatial \
  --env.fps=20 \
  --env.control_mode=relative \
  --env.max_parallel_tasks=1 \
  --eval.batch_size=1 \
  --eval.n_episodes=1 \
  --seed=1000 \
  --rename_map='{"observation.images.image":"observation.images.camera1","observation.images.image2":"observation.images.camera2"}' \
  --output_dir=/path/to/we_smolvla/outputs/eval/libero_spatial_smoke
```

验收：

- 环境完成 reset。
- 策略开始产生动作。
- episode 正常结束。
- 输出目录生成 `eval_info.json`。
- `overall.n_episodes` 等于实际任务数乘以每个任务 episode 数。
- `per_task` 中包含每个 task 的 `successes` 和 `video_paths`。
- 终端打印 `End of eval`。
- 终端无持续 OOM 或 EGL 错误。

检查输出：

```bash
python -m json.tool /path/to/we_smolvla/outputs/eval/libero_spatial_smoke/eval_info.json
find /path/to/we_smolvla/outputs/eval/libero_spatial_smoke/videos -type f -name '*.mp4' | sort
```

该小规模评估的正确总 episode 数：

```text
libero_spatial 有 10 个 task
--eval.n_episodes=1
总 episode = 10 × 1 = 10
```

## 9. 四个标准 suite 评估

论文级标准协议为：

```text
4 个 suite
每个 suite 全部 task
每个 task 10 个 episode
```

命令：

```bash
conda activate lerobot_043
cd /path/to/we_smolvla
export MUJOCO_GL=egl
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1

lerobot-eval \
  --policy.path=/path/to/we_smolvla/models/smolvla_libero \
  --policy.device=cuda \
  --policy.n_action_steps=10 \
  --env.type=libero \
  --env.task=libero_spatial,libero_object,libero_goal,libero_10 \
  --env.fps=20 \
  --env.control_mode=relative \
  --env.max_parallel_tasks=1 \
  --eval.batch_size=1 \
  --eval.n_episodes=10 \
  --seed=1000 \
  --rename_map='{"observation.images.image":"observation.images.camera1","observation.images.image2":"observation.images.camera2"}' \
  --output_dir=/path/to/we_smolvla/outputs/eval/libero_standard
```

预期总 episode 数：

```text
libero_spatial: 10 个 task × 10 个 episode/task = 100
libero_object:  10 个 task × 10 个 episode/task = 100
libero_goal:    10 个 task × 10 个 episode/task = 100
libero_10:      10 个 task × 10 个 episode/task = 100
总计: 400 个 episode
```

检查输出完整性和字段：

```bash
python - <<'PY'
import json
from pathlib import Path

output_dir = Path("/path/to/we_smolvla/outputs/eval/libero_standard")
info = json.loads((output_dir / "eval_info.json").read_text())

print("overall:", info["overall"])
for name, metrics in info["per_group"].items():
    print(
        name,
        "episodes=", metrics["n_episodes"],
        "success=", metrics["pc_success"],
        "avg_reward=", metrics["avg_sum_reward"],
    )

video_count = sum(1 for _ in (output_dir / "videos").rglob("*.mp4"))
expected = sum(len(row["metrics"]["successes"]) for row in info["per_task"])
print("video_count:", video_count)
print("expected_episodes:", expected)

assert info["overall"]["n_episodes"] == expected
assert video_count == expected
print("standard_result_complete: True")
PY
```

`eval_info.json` 包含：

```text
overall
per_group
per_task
```

`per_task` 中每项包含：

```text
task_group
task_id
metrics
```

12 GB 显存下不要先尝试增大 `batch_size`。先完成小规模测试，再根据峰值显存决定。

## 10. 训练链路冒烟测试

使用公开 LIBERO 数据集执行极少步数训练，只验证训练、保存和加载流程。

```bash
conda activate lerobot_043
cd /path/to/we_smolvla
export MUJOCO_GL=egl
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True

lerobot-train \
  --policy.type=smolvla \
  --policy.load_vlm_weights=true \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --dataset.repo_id=lerobot/libero \
  --dataset.video_backend=torchcodec \
  --output_dir=/path/to/we_smolvla/outputs/train/libero_smoke_043 \
  --job_name=libero_smolvla_smoke_043 \
  --batch_size=1 \
  --steps=200 \
  --num_workers=2 \
  --log_freq=10 \
  --save_freq=100 \
  --eval_freq=0 \
  --policy.use_amp=true \
  --wandb.enable=false
```

说明：

- `--policy.type=smolvla` 让输入和输出维度从 LIBERO 数据推断。
- `--policy.load_vlm_weights=true` 加载 SmolVLM 预训练视觉语言权重。
- 训练冒烟直接使用 LIBERO 的 `observation.images.image` 和
  `observation.images.image2`，不要传入评估模型使用的 rename map。
- `--eval_freq=0` 关闭训练中的环境评估。
- `200` 步只验证链路，不用于评价模型质量。
- `0.4.3` 不支持 `--eval_steps` 和 `--env_eval_freq`。

检查输出：

```bash
find /path/to/we_smolvla/outputs/train/libero_smoke_043 -maxdepth 4 -type f | sort | head -80
```

重点检查：

```text
checkpoints/last/pretrained_model/config.json
checkpoints/last/pretrained_model/model.safetensors
checkpoints/last/pretrained_model/train_config.json
```

加载检查点：

```bash
python - <<'PY'
import torch
from lerobot.policies.smolvla import SmolVLAPolicy

path = "/path/to/we_smolvla/outputs/train/libero_smoke_043/checkpoints/last/pretrained_model"
policy = SmolVLAPolicy.from_pretrained(path)
policy = policy.to(torch.device("cuda"))
policy.eval()
print("loaded:", path)
print("type:", policy.config.type)
print("chunk_size:", policy.config.chunk_size)
print("n_action_steps:", policy.config.n_action_steps)
PY
```

## 12. 仿真训练是否继续的判断

只有以下条件成立才进入本地数据训练：

- LIBERO Spatial 小规模评估成功完成。
- 标准 suite 评估完成，或已明确记录省略的 suite。
- 训练冒烟测试至少保存一个可重新加载的检查点。
- 峰值显存低于 11 GiB，并保留约 1 GiB 余量。
- 没有持续出现 NaN、数据解码错误或环境崩溃。

不要用 200 步冒烟模型的成功率作为算法结论。

## 14. 常见问题

| 现象 | 处理 |
| --- | --- |
| `MUJOCO_GL` 相关错误 | 切换 EGL/OSMesa，确认无显示服务器依赖 |
| LIBERO import 失败 | 在 `lerobot_043` 中安装 `.[libero]` |
| 相机键不匹配 | 加入 `--rename_map` |
| 动作维度不匹配 | 使用 LIBERO 兼容模型，或从 `lerobot/libero` 微调 |
| 执行 50 步后表现差 | 设置 `--policy.n_action_steps=10` |
| `env.fps` 改变后表现异常 | 固定 `--env.fps=20` |
| 12 GB 显存 OOM | batch 降为 1，关闭视频录制，先不进行训练中环境评估 |
| `Unknown scheme for proxy URL socks://...` | 清理 SOCKS 代理变量或使用已缓存模型离线加载 |
| IDE 将成功评估标记为失败 | 检查 `End of eval`、`eval_info.json` 和退出码 |
