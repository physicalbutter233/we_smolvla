# SmolVLA 部署项目指导书

## 1. 目标

本阶段完成软件环境、机械臂、摄像头、模型加载和基础遥操作验证。

本阶段不进行正式数据采集，不进行正式训练，不进行模型自动控制测试。

本项目统一使用：

```text
Conda 环境: lerobot_043
Python: 3.10
LeRobot: 0.4.3
源码目录: /path/to/we_smolvla
```

不使用 `lerobot-rollout`，因为 LeRobot `0.4.3` 不提供该命令。

## 2. 交付物

完成本指导书后应得到：

- 一个 Python 3.10 的 `lerobot_043` 环境。
- 可运行的 LeRobot `0.4.3` CLI。
- 可加载的 `lerobot/smolvla_base`。
- 已校准的 SO-100 或 SO-101 leader 和 follower。
- 已识别并固定配置的摄像头。
- 一份记录端口、设备 ID、版本和验证结果的部署记录。

路径分散。

## 4. 环境创建和安装

### 4.1 运行环境选择

首轮使用 Miniforge。原因是本阶段需要直接验证两个 USB 串口机械臂、多个摄像头、
校准、遥操作、回放和模型加载。Miniforge 在宿主机上直接运行，不需要额外处理设备
映射、设备组权限和图形显示转发。

Docker 可选，但不应作为真实机械臂首轮闭环的默认环境。Docker 更适合只运行
LIBERO 仿真、数据处理或训练。若使用 Docker 控制真实机械臂，需要处理：

- GPU 访问：安装 NVIDIA Container Toolkit，并使用 `--gpus all`。
- 串口访问：映射 `/dev/ttyACM0`、`/dev/ttyACM1` 或稳定设备路径。
- 组权限：把宿主机的 `dialout` 组 GID 映射到容器用户。
- 摄像头访问：映射 `/dev/video*`，并映射摄像头设备组 GID。
- 图形显示：需要摄像头窗口或 Rerun 窗口时配置 X11/Wayland 转发。
- 数据持久化：把项目目录、模型、数据集和输出目录挂载到宿主机目录。

Docker 命令结构参考如下，实际设备号和 GID 必须先检查，不能直接照搬：

```bash
docker run --rm -it \
  --gpus all \
  --ipc=host \
  --device=/dev/ttyACM0:/dev/ttyACM0 \
  --device=/dev/ttyACM1:/dev/ttyACM1 \
  --device=/dev/video0:/dev/video0 \
  --device=/dev/video1:/dev/video1 \
  --group-add "$(getent group dialout | cut -d: -f3)" \
  --group-add "$(getent group video | cut -d: -f3)" \
  -v /path/to/we_smolvla:/workspace \
  -w /workspace \
  <lerobot-043-image>
```

后续命令默认在宿主机的 `lerobot_043` 环境中执行。

## 7. 模型加载验证

```bash
conda activate lerobot_043
cd /path/to/we_smolvla

python - <<'PY'
import torch
from lerobot.policies.smolvla import SmolVLAPolicy

model_path = "/path/to/we_smolvla/models/smolvla_base"
policy = SmolVLAPolicy.from_pretrained(model_path)
policy = policy.to(torch.device("cuda"))
policy.eval()

print("policy_type:", policy.config.type)
print("chunk_size:", policy.config.chunk_size)
print("n_action_steps:", policy.config.n_action_steps)
print("input_features:", policy.config.input_features)
print("output_features:", policy.config.output_features)
print("empty_cameras:", policy.config.empty_cameras)

if torch.cuda.is_available():
    print("gpu_memory_allocated_mb:", torch.cuda.memory_allocated() / 1024**2)
    print("gpu_memory_reserved_mb:", torch.cuda.memory_reserved() / 1024**2)
PY
```

该步骤只验证模型加载，不验证机器人动作。

如果出现代理错误：

```text
OSError: Unknown scheme for proxy URL URL('socks://127.0.0.1:7897/')
```

先清理当前终端中的 SOCKS 代理变量，或改用已经缓存的模型：

```bash
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY
unset http_proxy https_proxy all_proxy
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

需要重新下载模型时，单独打开一个新的联网终端，并确保代理是 HTTP、HTTPS 或
`socks5h://`，不要把 `socks://` 写入环境变量。

## 8. 串口权限

查看当前用户组：

```bash
id
groups
```

将用户加入 `dialout`：

```bash
sudo usermod -aG dialout "$USER"
```

执行后注销并重新登录，或者重启系统。

检查串口：

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
```

不要长期依赖：

```bash
sudo chmod 666 /dev/ttyACM0
```

这种方式在重新插拔或重启后可能失效，并且权限范围过大。

## 9. 查找机械臂端口

先连接 follower，只保留这一组设备，然后运行：

```bash
conda activate lerobot_043
lerobot-find-port
```

记录 follower 端口，例如：

```text
/dev/ttyACM0
```

再连接 leader，并再次运行：

```bash
lerobot-find-port
```

记录 leader 端口，例如：

```text
/dev/ttyACM1
```

建议始终使用相同 USB 物理端口，以降低端口变化概率。

## 11. 校准机械臂

设备和 ID 必须保持一致。推荐：

```text
follower type: so101_follower
follower id: so101_follower_main
leader type: so101_leader
leader id: so101_leader_main
```

### 11.1 校准 follower

```bash
conda activate lerobot_043

lerobot-calibrate \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.id=so101_follower_main
```

### 11.2 校准 leader

```bash
lerobot-calibrate \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM1 \
  --teleop.id=so101_leader_main
```

校准要求：

- leader 和 follower 处于相同机械零点附近。
- 每个关节完整经过工作范围。
- 校准过程中不碰撞桌面或线缆。
- 校准后重复执行一次，确认结果一致。

## 12. 查找摄像头

查询设备：

```bash
conda activate lerobot_043
lerobot-find-cameras opencv
```

首轮统一使用 640x480、30 FPS。记录每个物理摄像头对应的 index：

```text
camera1: 顶部全局视角
camera2: 腕部视角
camera3: 侧向补充视角
```

如果只有两个摄像头：

```text
camera1: 顶部全局视角
camera2: 腕部视角
camera3: 缺失
```

缺少的视角由 `--policy.empty_cameras=1` 处理。

新录数据时优先直接把摄像头命名为 `camera1` 和 `camera2`。如果已经使用
`front` 和 `wrist` 录制，训练时必须提供：

```bash
--rename_map='{"observation.images.front":"observation.images.camera1","observation.images.wrist":"observation.images.camera2"}'
```

不要把 `camera1` 和 `camera2` 的物理位置互换后继续使用旧数据。

## 13. 遥操作验证

`0.4.3` 的命令入口是：

```text
lerobot-teleoperate
```

底层脚本模块是：

```text
lerobot.scripts.lerobot_teleoperate
```

不要使用旧路径：

```bash
python -m lerobot.teleoperate
```

`0.4.3` 不存在该模块，报错为：

```text
No module named lerobot.teleoperate
```

如果需要以模块方式启动，使用：

```bash
python -m lerobot.scripts.lerobot_teleoperate --help
```

遥操作命令只实时读取 leader、驱动 follower，并显示数据，不保存训练数据集。
正式采集数据使用 `03_数据收集与格式处理项目指导书.md` 中的 `lerobot-record`。

双摄示例：

```bash
conda activate lerobot_043

lerobot-teleoperate \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.id=so101_follower_main \
  --robot.cameras="{ camera1: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, camera2: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30} }" \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM1 \
  --teleop.id=so101_leader_main \
  --display_data=true
```

三摄示例：

```bash
lerobot-teleoperate \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.id=so101_follower_main \
  --robot.cameras="{ camera1: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, camera2: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30}, camera3: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30} }" \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM1 \
  --teleop.id=so101_leader_main \
  --display_data=true
```

验收要求：

- follower 跟随 leader，不存在关节方向相反。
- 动作范围完整，无卡死或异常抖动。
- 摄像头画面稳定，没有持续延迟累积。
- 终端 cadence 报告接近目标 30 Hz。

## 16. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| `torch.cuda.is_available()` 为假 | 是否安装 CUDA wheel、驱动是否加载、是否为 CPU wheel |
| 找不到 `lerobot-teleoperate` | 是否激活 `lerobot_043`、是否从 `/path/to/we_smolvla` editable 安装 |
| `No module named lerobot.teleoperate` | 不要使用旧模块路径，使用 `lerobot-teleoperate` CLI |
| 无权限打开 `/dev/ttyACM*` | `dialout` 用户组、是否重新登录 |
| 机械臂方向相反 | 校准、电机 ID、leader/follower 类型 |
| 摄像头帧率低 | USB 控制器带宽、分辨率、同时打开的程序 |
| 摄像头画面交叉 | 物理摄像头和 index 映射 |
| `command not found: hf` | `huggingface_hub` CLI 是否安装、环境是否激活 |
| `Unknown scheme for proxy URL socks://...` | 清理 SOCKS 代理变量或使用已缓存模型离线加载 |
