# 数据收集与格式处理项目指导书

## 1. 目标

本阶段完成：

1. 使用 SO-100 或 SO-101 leader/follower 收集本地遥操作数据。
2. 数据直接写入 LeRobotDataset v3。
3. 检查摄像头、状态、动作、任务文本和时间戳。
4. 删除坏 episode。
5. 按 episode 拆分 train、val、test。
6. 冻结数据版本并记录哈希。

本项目统一在 `lerobot_043` 中完成录制、检查、编辑和训练数据准备：

```text
conda 环境: lerobot_043
Python: 3.10
LeRobot: 0.4.3
源码目录: /path/to/we_smolvla
```

`lerobot-record` 已经直接生成目标格式。不要自己重新编码视频、改变字段名或手工
拼接 parquet，除非使用外部数据源并且已经完成单独的转换验证。

当前项目已经生成并验证了一份 `camera12` 字段规范化副本。后续新录数据应直接在
`--robot.cameras` 中使用 `camera1`、`camera2`，不要重复手工修改已有数据。


检查目录结构：

```bash

  -maxdepth 3 -type f | sort | head -80
```

典型结构：

```text
dataset_root/
├── meta/
│   ├── info.json
│   ├── stats.json
│   ├── tasks.jsonl 或 tasks.parquet
│   └── episodes/
├── data/
│   └── *.parquet
└── videos/
    └── **/*.mp4
```

SmolVLA 基础模型的关键字段：

```text
observation.state
observation.images.camera1
observation.images.camera2
observation.images.camera3
action
task
```

原始副本的摄像头字段是：

```text
observation.images.front
observation.images.wrist
```

字段规范化副本已经改为：

```text
observation.images.camera1
observation.images.camera2
```

训练字段规范化副本时不需要 `rename_map`，但仍需提供：

```bash
--policy.empty_cameras=1
```

只有训练原始副本时，才需要：

```bash
--rename_map='{"observation.images.front":"observation.images.camera1","observation.images.wrist":"observation.images.camera2"}'
--policy.empty_cameras=1
```

如果以后重新录制，优先直接把摄像头命名为 `camera1`、`camera2` 和可选的
`camera3`，这样新的数据不需要 `rename_map`。

SO-100/SO-101 的 state 和 action 通常为 6 维。SmolVLA 内部会把它们填充到
`max_state_dim=32` 和 `max_action_dim=32`。

## 3. 摄像头和任务文本约定

推荐固定为：

```text
camera1: 顶部全局视角，保证物体、夹爪和目标区域都可见
camera2: 腕部视角，保证夹爪和被抓物体可见
camera3: 侧向视角，用于补充深度和遮挡信息
```

只有两个摄像头时：

```text
camera1: 顶部全局视角
camera2: 腕部视角
camera3: 不存在
```

训练和推理时加入：

```bash
--policy.empty_cameras=1
```

任务文本使用稳定英文命令句。示例：

```text
Pick up the blue cube and place it in the box.
```

录制、训练、评估和本地测试使用完全相同的字符串。不要在不同阶段改写大小写、
标点或位置描述。

## 7. 录制过程中的控制键


```bash
print("episodes:", ds.num_episodes)
print("frames:", ds.num_frames)

for key, value in ds.features.items():

print("info_exists:", (Path(root) / "meta" / "info.json").exists())
print("stats_exists:", (Path(root) / "meta" / "stats.json").exists())
PY
```

### 9.3 检查所有 episode 的有限值

```bash
conda activate lerobot_043
cd /path/to/we_smolvla

python - <<'PY'
from pathlib import Path
import numpy as np
from lerobot.datasets.lerobot_dataset import LeRobotDataset

repo_id = "local/so101_pick_blue_cube_camera12"
root = "/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12"

ds = LeRobotDataset(repo_id=repo_id, root=root)
print("episodes:", ds.num_episodes)
print("frames:", ds.num_frames)
print("camera_keys:", ds.meta.camera_keys)

for episode_idx in range(ds.num_episodes):
    start = int(ds.meta.episodes["dataset_from_index"][episode_idx])
    end = int(ds.meta.episodes["dataset_to_index"][episode_idx])
    length = end - start
    sample = ds[start]
    state = sample["observation.state"].numpy()
    action = sample["action"].numpy()

    if not np.isfinite(state).all():
        raise RuntimeError(f"state has non-finite values in episode {episode_idx}")
    if not np.isfinite(action).all():
        raise RuntimeError(f"action has non-finite values in episode {episode_idx}")

    print("episode", episode_idx, "frames", length)

meta_root = Path(root)
for name in ["info.json", "stats.json"]:
    print(name, "exists:", (meta_root / "meta" / name).exists())
PY
```

读取、字段检查或视频解码任一失败，都不得进入训练阶段。先解决格式问题，不要在
训练命令中绕过数据错误。

## 10. 删除坏 episode

不要直接删除 parquet 或 mp4 文件。使用 `0.4.3` 的编辑工具：

```bash
conda activate lerobot_043
cd /path/to/we_smolvla

lerobot-edit-dataset \
  --repo_id=local/so101_pick_blue_cube_camera12 \
  --root=/path/to/we_smolvla/datasets \
  --new_repo_id=local/so101_pick_blue_cube_camera12_clean \
  --operation.type=delete_episodes \
  --operation.episode_indices="[3, 8, 12]"
```

说明：`0.4.3` 的 `lerobot-edit-dataset` 对 `--root` 的语义是数据集仓库的父目录。
因此上面的输出目录是：

```text
/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12_clean
```

需要删除的典型 episode：

- 摄像头黑屏、严重遮挡或明显掉帧。
- 操作者中途犹豫、停住或多次撤销。
- 物体被意外碰出工作区。
- 夹爪碰撞桌面但不代表目标策略。
- 任务文本和实际行为不一致。

## 11. 任务文本处理

LeRobot `0.4.3` 的 `lerobot-edit-dataset` 不支持 `modify_tasks`。正确做法是在
录制时使用最终任务文本，并保持后续训练、评估和本地测试使用同一字符串。

如果发现旧数据任务文本错误，不要直接修改 parquet。优先重新录制，或者在确认
`LeRobotDataset` 元数据结构和写入接口后编写单独的数据修复脚本，并在复制的数据集上
验证。

## 12. 拆分 train、val、test

必须按 episode 拆分，不能按帧随机拆分，否则同一 episode 的连续帧会泄漏到验证集和
测试集。

`0.4.3` 的 `lerobot-edit-dataset --operation.type=split` 会把输出写到默认
Hugging Face 缓存位置，并且没有 `--new_root` 参数。若要把拆分结果固定到项目目录，
使用以下 Python 调用：

```bash
conda activate lerobot_043
cd /path/to/we_smolvla

python - <<'PY'
from pathlib import Path
from lerobot.datasets.lerobot_dataset import LeRobotDataset
from lerobot.datasets.dataset_tools import split_dataset

source_repo_id = "local/so101_pick_blue_cube_camera12_clean"
source_root = "/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12_clean"
output_root = Path("/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12_split")

splits = {
    "train": list(range(0, 21)),
    "val": list(range(21, 25)),
    "test": list(range(25, 30)),
}

dataset = LeRobotDataset(source_repo_id, root=source_root)
split_dataset(dataset, splits=splits, output_dir=output_root)
print("output_root:", output_root)
PY
```

输出目录：

```text
/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12_split/train
/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12_split/val
/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12_split/test
```

对应的内部 `repo_id`：

```text
local/so101_pick_blue_cube_camera12_clean_train
local/so101_pick_blue_cube_camera12_clean_val
local/so101_pick_blue_cube_camera12_clean_test
```

推荐拆分原则：

- `train`：约占 70%。
- `val`：约占 15%。
- `test`：约占 15%。
- 测试集包含训练中未出现或较少出现的初始位置。
- 如果任务有 5 个关键位置，每个位置至少保留 1 至 2 个测试 episode。
- 如果录制是分批会话，应按会话和位置核对，防止同一场景泄漏。

## 13. 统计信息和数据冻结

`0.4.3` 没有 `recompute_stats` 编辑操作。删除和拆分工具会复制并重写 episode
统计数据，拆分后的数据集可以使用自身的：

```text
meta/stats.json
```

训练时 `LeRobotDataset` 会读取该文件。不要手工删除 `stats.json`，也不要手工拼接
统计文件。

检查拆分后数据的统计文件：

```bash
python - <<'PY'
from pathlib import Path

root = Path("/path/to/we_smolvla/datasets/processed/so101_pick_blue_cube_camera12_split")
for split in ["train", "val", "test"]:
```

## 14. 数据验收表

| 项目         | 验收标准                                                                      |
| ------------ | ----------------------------------------------------------------------------- |
| episode 数量 | 首轮不少于 50 个有效 episode                                                  |
| 变化覆盖     | 每个关键位置至少 10 个 episode                                                |
| 帧率         | 目标 30 Hz，cadence 报告稳定                                                  |
| 摄像头       | 无黑屏、无严重掉帧、顺序正确                                                  |
| 状态         | 维度为 6，数值有限，顺序固定                                                  |
| 动作         | 维度为 6，方向正确，回放可复现                                                |
| 文本         | 所有 episode 文本一致                                                         |
| 拆分         | train/val/test 按 episode 隔离                                                |
| 格式         | 通过 LeRobotDataset 加载                                                      |
| 兼容         | 使用 `camera12` 规范化副本时不需要 `rename_map`，仍需正确设置 `empty_cameras` |
| 版本         | 已记录哈希和元数据                                                            |
